1. **实现与 Git 状态脱节**：记忆、AI、capture/command 等大量文件未跟踪；README 已介绍这些功能，但本地提交历史尚未包含完整实现。先整理工作区，避免只提交文档漏交源码。
2. **路线图互相冲突**：FUTURE 原顶部建议 13/14，§6 却要求从 11 开始并称 12 尚待细化。本次已纠正直接行动指令，并把扩展列为条件触发候选。
3. **当前架构与历史草案混杂**：FUTURE §1.2 仍有旧菜谱布局、memory/index.md 草图，§1.3 留有旧 UUID 描述；本次纠正了 §1.4 的「必须有 SQLite」结论，其余需按现行 SPEC/格式规范归并，保留必要的历史纠正块。
4. **DESIGN 现在时漂移**：§1.3 仍将 AI 写成未来阶段，和该文档头部及现有实现不一致。SPEC 部署检查仍写 102 tests、测试汇总写 171，本次实测为 182。
5. **任务格式漂移**：01–16 使用中文/emoji 状态，部分完成文件通过改名标状态；后续统一为 draft / settled / in progress / done / cancelled。保留现有文件名以保护引用，不再新增完成后改名流程；全库检查历史断链。
6. **真实 AI 验收未闭合**：Task/11、12 均保留待真实模型验收项；模型 mock 与纯函数测试不能证明识别准确、跨模型可用或比手动更快。
7. **图片上传边界待验证**：`src/lib/utils/compress-image.ts` 使用尺寸/质量压缩，但失败会回退原图、GIF 会跳过；`next.config.ts` 没有配置 Server Action bodySizeLimit。不能把压缩视为请求必然小于传输上限的保证。需要以实际手机图片复现后再确定修改。
8. **撤销重复目标的边界待复现**：`src/lib/services/command/index.ts` 的 `applyProposal()` 对同一食材每次改动均记录快照，而 `src/lib/services/inventory/index.ts` 的 `restoreInventoryState()` 顺序恢复。若同一提案多次修改同一食材，静态分析提示可能恢复到中间状态；现有测试只覆盖单次修改。本次诊断脚本在进入业务逻辑前被本机 tsx 的 `uv_os_get_passwd ENOMEM` 错误中断，因此此项仍为待运行复现，不能记作已实测缺陷。

## 建议步骤

1. 阅读 `git status --short`、`git diff --stat`、`git diff --cached --stat` 和未跟踪文件列表，按记忆/AI录入/命令层梳理变更；保留已有暂存状态与工作成果，不用 reset 或整包覆盖。
2. 用测试临时 Vault 复现上面的回滚边界，检查构建 NFT 追踪警告；根据结果修复阻塞问题。改 Next.js 相关代码前先读 `node_modules/next/dist/docs/` 的对应指南。
3. 在独立验收 Vault 上运行应用；配置确认后用 `npx tsx --env-file=.env.local scripts/verify-ai.ts` 做真实请求冒烟。它会向已配置端点发送请求，执行前核实配置与样本；不要把 key 写进文档或提交。
4. 按 Task/11、12 的既有验收标准操作：10 样食材录入、记录做完一道菜、跨天排菜、记忆提示、确认与撤销。比较手动与 AI 全流程耗时，包含等待和纠错；验证实际文件状态，不能使用 `git diff data/` 为空作为唯一证据，因为默认 `data/` 被忽略。
5. 将结果回写原任务与 SPEC；统一状态、消除现状与旧草案冲突，逐条检查链接。只有达到验收条件才进入完成流程。
6. 建议再真实使用一周，记录是否愿意持续更新库存、哪一步最烦；按记录选择下一项改进。一周是观察窗口建议，不是已设定的自动化或承诺。

## 验收标准

- `npm run test`、`npm run lint`、`npm run build` 结果可复现，警告与限制如实记录。
- 买菜录入 → 推荐选菜 → 做完记账 → 库存更新完成一次真实闭环；模型的错误能确认、更正和撤销。
- Task/11 的「比手动快 3 倍」保留为待实测标准，未达成则分析瓶颈，不因功能可点击就判完成。
- 撤销还原库存档位与补货日期；重复目标、多次确认及失败后恢复有针对性验证。
- 工作区源码与文档的交付范围清楚，未跟踪实现不会在交付中遗漏；本轮评估不自动代替用户提交或发布。
- FUTURE 的任务链接存在，状态与任务头一致，依赖无循环；历史任务文件不因完成而再次改名。

## 风险与不做什么

- 不重写已实现的 11/12，不做模块平台、社区后端、向量库、SQLite 或多用户。
- 不重置、删除或上传作者的真实 Vault；验收使用独立数据副本。
- 不把单测通过、key 已配置或旧任务完成记录等同于真实体验验收。
- 不为消除警告而顺手做大规模重构；优先可复现的功能障碍与数据正确性。
